# Lesson Maker

A terminal slide workspace for authoring a lesson: the outline on the left, the slide preview and a fixed form of its fields in the middle, the lesson chat on the right. A lesson is one JSON file that follows [the lesson schema](schema/lesson.schema.json), so agents can write lessons directly and people edit on top. Every change saves to the file as it happens. The chat runs real models through the Pi installed on this machine, and image boxes generate pictures with Pi's imagegen extension. Keyboard and mouse (click, wheel and drag); no animation.

Status: new, unpublished. The offline suite, including an isolated real-PTY smoke, passes; real-Pi and simulated-input Herdr runs are recorded per change in [contributing](CONTRIBUTING.md#verification-record), and the [native check](CONTRIBUTING.md#native-check-still-needed) with a physical mouse and real Kitty placement is still open.

## Run

Node 22 and the repository's [root setup](../CONTRIBUTING.md#setup) are required to resolve the design-system package. No project install or additional dependencies. The chat and pictures need Pi on `PATH` (or `LESSON_MAKER_PI` set to its package folder) with at least one model logged in; the editor works without it.

To run it from any folder as `lesson`, link `main.mjs` into a folder on your `PATH` (Node follows the link back to the checkout, so the design-system package still resolves):

```sh
ln -s "$PWD/lesson-maker/main.mjs" ~/.local/bin/lesson
```

```sh
lesson                                   # start screen: this project's lessons, or a new one
lesson path/to/name.lesson.json
lesson --images=text path/to/name.lesson.json
lesson --validate path/to/name.lesson.json
lesson --plain --size=140x40 [path/to/name.lesson.json]
```

`node lesson-maker/main.mjs …` works the same without the link.

- **Start screen:** with no file, `lesson` finds the project (the git checkout the current folder is in, or the folder itself outside git) and lists its `*.lesson.json` files, newest first, under `+ New lesson...`. Hidden folders, `node_modules`, `dist`, `build`, `target`, `vendor` and picture folders are skipped; the search stops at 6 folders deep and 200 lessons. A new lesson is named on the screen and saved as `lessons/<name>.lesson.json` at the project root (lower case, words joined by `-`), creating `lessons/` if needed. Enter or a click opens, Up/Down choose, Esc goes back, q or Ctrl-C quits.

- **Opening:** a missing file is created as a blank lesson. A file that breaks the schema opens **read only**, with each error and its JSON path listed; nothing is written to it until it is fixed outside the app and reopened.
- **Saving:** every saved box, choice and outline change writes the whole file at once (a temporary file, flushed, then renamed over it), but only if the lesson still follows the schema; the header says `SAVED`, or `NOT SAVED · n problems` with the reasons one click away. Quitting saves text still being typed.
- **Pictures** live in a folder beside the lesson named after it (`name.lesson.assets/`); the file stores their paths relative to its own folder. Files are never deleted.
- **History** lives in a second folder beside the lesson (`name.lesson.history/`), which the app only adds to. Just before each AI request that can change the lesson starts (a box, slide or whole-lesson message, `[generate]`, and once for each `g` batch, not per picture), the saved file is copied there as `<local time>.lesson.json` (such as `2026-11-10T14-55-07-123.lesson.json`), unless it is byte-identical to the newest copy; pictures are not copied (they are never deleted). If the copy cannot be written, the request does not run and the chat says so. Each finished chat entry (your messages, replies and failures, not the live progress lines) is added to `chat.jsonl` there, one JSON object a line (`time`, `role`, `scope`, `stamp`, `text`). Opening the lesson shows the last 200 of them in the chat, marked `earlier`; they are only shown, never sent to a model. A lesson that opened read only, or has no file, adds nothing to it. To go back to a copy, open it or copy it over the lesson outside the app.
- `--validate` prints each schema error with its JSON path, or that the file follows the schema; exit code 1 means errors. `--plain` is an escape-free text snapshot that never writes; without a file it shows the bundled [example lesson](examples/browser-caching.lesson.json).
- `--images=auto` is the default. Auto admits an interactive Herdr/known Kitty identity only, rejecting tmux/screen/dumb and non-TTY. `--images=kitty` is an informed override, not proof of compatibility. `NO_COLOR` forces text images even with forced Kitty.

Minimum **100×24**, or **80×30** in one column. Below it, a resize screen keeps unsaved typing and requests and accepts only q and Ctrl-C.

## The lesson file

[`schema/lesson.schema.json`](schema/lesson.schema.json) (JSON Schema 2020-12) is the contract for agents: the lesson plan (outcomes, prerequisites, teaching principles, progression), then sections, each with its linked title slide, its own slides and subsections. Every slide carries every field whatever its layout, so a slide always maps onto the same form; only `tagline` (the short line on a Title + image slide), `comments` (the author's review comments) and `locked` are optional, so lessons written before them stay valid; the app writes `tagline` on every slide, `comments` only when there are some and `locked` only when it is true. Slides no longer have `keyPoints`: opening a lesson that has them moves each slide's key points to the top of its speaker notes and writes the file back without them (`--plain` and `--validate` read the moved version without writing). Ids must be unique in the lesson; the app checks that beside the schema. Pictures are `null`, `{ "source": "attached", "file" }` or `{ "source": "generated", "file", "prompt", "model" }`. The app's validator implements exactly the keywords the schema uses and refuses any other, so a schema change cannot ask for a check that silently does not happen.

## AI

At start the app loads Pi's SDK from the installed Pi, with only the Pi extensions that register model providers (such as claude-bridge) and the one that registers imagegen; others (prompts, memory, tools) do not shape lesson edits. It also finds the `ian-xiaohei-illustrations` skill where Pi has it installed, for Xiaohei pictures; no other skill is used. The chat offers every model Pi has logged in, starting with Pi's default model.

- **Aimed at a box** (focus the box, then `Ctrl-G`): the model gets the lesson, the box, what it is for and the recent chat, and replies with the box's new text, which replaces it. The box is locked while the request waits or runs. Requests on the same box run in order, each on the previous one's result; different boxes run side by side.
- **Aimed at the whole lesson:** the model may change anything (plan, sections, slides, order, text, layouts, types, image concepts, picture styles) through small tools: `delete_items`, `add_slide`, `add_group`, `move_items`, `set_slides` and `set_plan`. Each applies at once, only if the lesson still passes the schema (errors go back to the model with JSON paths), and adds a line such as `· Deleted Slide 4 "…"` to the chat. `update_lesson`, which takes a complete new lesson, is kept for rewriting most of it; while the model writes a long change the chat counts its characters. The model can also generate pictures, with its own prompt if it likes, and has the Xiaohei skill: its instructions in the request, with its reference files to read. **It claims first:** before changing anything it calls `claim_slides` with the slides, subsections or sections it will change (`plan: true` for the plan; `all: true`, only as its first claim, for `update_lesson`), and may claim more later. Until its first claim everything is locked, as it is while the request waits; after it, only what it claimed (a claimed group with its title slide, slides and subsections) is locked to you and to other requests, and you can edit the rest, and send box and slide requests on other slides, which run beside it. A claim is refused, item by item, for a slide you locked, one another request is on, or one you are typing in, and the model is told why. Its tools refuse anything outside its claim; adding, moving or deleting needs every group whose slides change claimed, the destination of a move included, and a new section is claimed for it. The chat entry lists what it claimed (`· Claimed slides 1–51`); everything is released when it ends. Whole-lesson requests still run one at a time. `u` in the outline undoes all of the request's changes at once, and leaves what you changed beside it; it refuses if something the request changed was changed again since.
- **Reference material:** every request can read, but not change, files and artifacts. Pi's read-only tools (`read`, `ls`, `find`, `grep`) start at the lesson's project folder. `read_document` turns a local file, a 12-character artifact id or an artifact link into text, 40,000 characters at a time. HTML loses its markup and keeps slide text that a page holds in its scripts. An image is handed to `read`. `list_artifacts` lists your unexpired artifacts. Artifacts need an artifact CLI that supports `artifacts download <id-or-link> --output <file> --json` and `artifacts list --no-expired --json --limit <n>` with JSON output: start the app with `LESSON_MAKER_ARTIFACT_CLI=<artifact-cli>` (a command on `PATH` or a path), and with `LESSON_MAKER_ARTIFACT_HOST=<host>` to accept `https://<host>/<id>` links as well as ids. Without the CLI both tools answer that artifacts are unavailable. Artifacts are fetched with that CLI's own login; if it fails, the tool hands the error to the model instead of text.
- Boxes an AI changed carry `◆ AI EDIT`. Review only stops running requests at once and starts nothing new.
- **White behind pictures:** with Kitty images, every picture (in the preview and the large view) sits on white cells, so a transparent picture reads as a white slide; a margin the terminal's cell size leaves round it is white too.
- **Picture style:** each image box's bottom border starts with a `[Generic ▾]` button that opens a small dropdown of Generic and Xiaohei; the choice is saved with the image (`style` in the file; absent means generic). Either way the chat model first writes the picture's prompt (one extra model call, in English) from the image concept and the whole lesson, so pictures keep the lesson's names, examples and metaphors: Generic asks for a flat teaching diagram; Xiaohei follows the skill and all its reference files; the skill's example pictures are not sent, as the skill says they are not for copying.
- **Saved picture prompts** stay in the file but are left out of the lesson every model request is given: they are long and mostly repeated style text (a 161-slide lesson's came to about 700 KB, which pushed whole-lesson requests over Google's input-tokens-per-minute limit). Whole-slide and whole-lesson requests read one with `picture_prompt` (the slide and `image` or `afterImage`) when a message or comment is about what a picture shows. A picture the model keeps without its prompt keeps its saved one.
- **Pictures:** `[generate]` on an image box sends the prompt for its style to imagegen at its saved default model in Pi (`/img` in Pi changes it), asking for an opaque background, saves the PNG into the picture folder, and records the exact prompt and the model in the file. `[prompt]` shows them, or what `[generate]` would send. `[attach PNG]` copies a local PNG into the folder instead: regular file, at most 16 MiB and 4096 pixels a side, noninterlaced 8-bit gray/RGB/RGBA. `u` in the outline brings back the previous picture.
- **Image backend:** imagegen uses its ChatGPT/Codex subscription unless `LESSON_MAKER_IMAGE_BACKEND=api` is set at start, which sends `backend: "api"`: the OpenAI Images API, **billed per image** on that API account. imagegen reads `OPENAI_API_KEY` from the app's environment itself; Lesson Maker only checks that it is there and never reads or shows it. `subscription` (or leaving it unset) keeps the subscription; any other value, or `api` without the key, stops the start with a message. With the key in Passbolt: `OPENAI_API_KEY='passbolt://<resource-id>' LESSON_MAKER_IMAGE_BACKEND=api passbolt exec -- lesson path/to/name.lesson.json`.

Requests think at a low level, whatever Pi's default is: at Pi's `high`, gemini-3.8-flash spent over 80 s looking around folders on a request that needed no files, and at low it finished in 8 to 13 s. Whole-lesson messages sent while one is running wait, then run together as one request.

Each request is a fresh in-memory Pi session: nothing is saved in Pi's session history, and requests keep no hidden memory beyond the recent chat they are given (this session's only; chat restored from the history is not sent).

## Keys and mouse

Every click has a key. The live `?` help lists them all.

- **Move:** click any form box, option, tab, button or outline row, or use `Tab`/`Shift-Tab` (the speaker notes, which sit first under the slide, then the comments, then the slide's boxes, layout, placement, the teaching plan, each image box with its buttons, then the header). The slide itself is a preview: only its pictures take clicks, and a click (or `z`) shows the picture over the whole window, sharp from the full PNG, on white; Esc or any click closes it. Arrows rove options; `Enter` or `Space` chooses. `[`/`]` or the `‹ ›` arrows change slide. `v` or the numbered top-bar tabs switch between the lesson plan's four parts (1 Outcomes, 2 Prerequisites, 3 Principles, 4 Progression), 5 Slides and 6 Learner preview.
- **Highlight and copy:** drag across text in a box or the message, or hold Shift with the arrows; the highlight is copied to the clipboard at once (OSC 52, which Herdr and Ghostty pass on), and Backspace deletes it or typing replaces it.
- **Edit:** the boxes under the slide are a form with every field always in the same place; fields the layout does not use are greyed out. A focused box is outlined in accent and takes typing at once; the slide preview updates as you type. Leaving the box saves it: Tab, Esc, a click elsewhere, Ctrl-G or a slide change. Enter is a new line in every box; Ctrl-S saves without leaving. Clicking a line puts the caret there; a box with more text than fits scrolls with the wheel and shows a rail.
- **Text:** readline and macOS editing keys: Ctrl-A/E/B/F/D/K/U/W, Option-←/→ and Option-Backspace by word, Cmd-←/→ when the terminal sends them.
- **Pictures from the chat:** a request on an image box rewrites the concept and generates the picture; slide and lesson requests about an image generate it themselves. `[generate]` stays for making one by hand.
- **Chat:** the aim follows focus. A message sent while a box is focused (or from the chat, opened from that box) rewrites that box; with no box focused it is a **whole-slide** request, which may change any of the current slide's fields (one `set_slide` call, plus `generate_picture` for that slide) and nothing else, and holds that slide's boxes while it runs. `0` or the `[whole lesson]` button aims at the whole lesson until you focus a box or change slides; the button then reads `[this slide]` and switches back. Outside the Slides view the chat aims at the whole lesson. A locked slide refuses slide requests. `Ctrl-G` or a click on the message box starts typing; `Ctrl-G` returns where you were. In chat, `Tab` cycles composer, transcript, effort, model and whole-lesson; the model button (or Enter on it) lists every model. PgUp/PgDn or the wheel scroll.
- **Aim check:** before a message aimed at a box or a slide goes (or one aimed at the whole lesson from a slide), Jev (TypeSafe, through Pi's `pi-typesafe` extension, a few hundred milliseconds) reads it with the last six chat messages and the slide titles and judges which scope it needs: that box, the slide or the whole lesson. If its top pick is another scope, or it reads the message as reaching beyond the slide (a second yes/no question in the same call, which a long list of writing preferences cannot drown out), a dialog asks where to send it, Jev's pick first (`Run on Whole lesson - may change anything` / `Keep on Slide 1 "…"`); Esc sends nothing and puts the message back in the box. When Jev agrees, is unsure, or is unavailable (with a notice), the message goes as aimed. Without `pi-typesafe` in Pi there is no check.
- **Effort:** the `[low]` button beside the model picks low, medium or high for every request: the chat model's thinking level, and for pictures imagegen's thinking and quality (low leaves imagegen's defaults; medium and high ask for that quality). Higher is slower. The model and effort are kept for the next start in `~/.config/lesson-maker/settings.json`.
- **Context use:** after a request, the status row shows `ctx N%`, how much of its model's context window that request filled (bold from 80%). Nothing compacts: every request starts a fresh session with the whole lesson and the last 8 chat messages, so this is how close a lesson is to being too big for the model.
- **Outline:** sections and subsections are tagged, and each one's row is its title slide (click it to open that slide); and `[+ slide]`, `[+ subsection]` and `[+ section]` at its foot add beside the current slide. Drag a slide row onto a slide to put it before that slide, or onto a section or subsection row to put it first there; drag a section or subsection row to move the whole group. `Ctrl-O` focuses it (a full panel below 150 columns). `o` or `[o hide]` on its header hides the column so the slide and form are wider and the slide taller (about 16:9, up to 170 columns and 55% of the height); `o` or `[o outline]` at the start of the slide's title row shows it again, and `Ctrl-O` still opens it as a panel. Hiding lasts for the session. Arrows and Enter open, Left/Right or the carets fold, and `n` `r` `m` `u` `d` create, rename, move, undo and delete. Deleting a group asks first; undo restores it.
- **Read aloud and present:** `[p read]`, `[P present]`, `[V Orus]` and `[s 1x]` sit beside the slide counter above the slide (dropped when the row is too narrow). `p` reads the current slide's speaker notes aloud (its title and text when it has no notes) with Google's `gemini-3.8-flash-tts` and macOS `afplay`, in the Orus voice unless `V` (or the voice button) picks another of Google's 30 (each listed with its gender and style; kept between runs); `p` again stops. `P` presents from the current slide in the editor itself: each slide is read in turn and the editor moves on as the voice finishes, with the next slide's voice prepared while the current one plays (a few seconds each). The speaker notes box highlights the words already spoken (an estimate from how much of the clip has played, since Google gives no word timings), and the slide's title row shows what the voice is doing with `[back] [pause] [next] [stop]`. Space pauses or resumes and Left/Right change slides when no box has the keyboard; P or Esc stops; choosing another slide moves the presentation there. A slide with nothing to read is skipped when the voice reaches it, but choosing one yourself (a new, empty slide, say) stops presenting and keeps it selected. Going into a box or the chat to type pauses it, so you can stop and write a comment; `[resume]` saves the box and carries on. `s` (or the speed button) steps the voice through 1x, 1.5x, 2x, 3x and 4x; a slide being read carries on from where it was at the new speed, and the speed is kept between runs with the model and effort. It uses the Google API key Pi has stored; nothing else to set up.
- **Review comments:** a COMMENTS box under the speaker notes holds your comments on each slide, saved in the lesson file as the slide's `comments` and never shown to learners. When you have reviewed the lesson, ask the chat to work through them (for example *look at my comments and make the adjustments*): the agent makes the change each comment asks for and clears that comment, and leaves any comment it could not act on, so what is left is still to do.
- **Every missing picture:** `g` (or `[g pictures]` under the outline) counts the image concepts in the whole lesson that have no picture yet, on unlocked slides with nothing running on the box, and asks `Generate N pictures?`. Confirmed, they run 8 at a time, at the chosen effort, with one chat entry counting done, working, waiting and failed, then listing failures. They count against the ChatGPT/Codex plan, which publishes no limit on images at once (or, with the API backend, are billed per image under the account's own rate limits, untested at 8 at once); a failure that reads like an exhausted limit (429, rate or usage limit) stops the ones still waiting, and `g` later picks up whatever is still missing.
- **Locks:** `l` (or `[l lock]` under the outline) locks the current row's slide; a section or subsection row is its title slide, so that locks the title slide alone. `L` (`[L lock all]`) locks every slide in the group, title slides and subsections included; pressing either again on an all-locked set unlocks it. Nobody can change, move or delete a locked slide until it is unlocked, neither you nor the AI: its boxes, options and image buttons take no focus (Tab skips them, a click says how to unlock), a group holding it cannot be moved or deleted, and undo refuses a step that would change it. Every agent change is checked against the locks before it applies, and the prompt tells the model about them. Locks are saved in the lesson file (`"locked": true`); a slide with an AI request waiting or running on it cannot be locked until the request ends.
- **Quit:** `q` or Ctrl-C. Everything is already saved, so `q` asks only while AI requests are running.

The example's diagrams are project-owned sample PNGs; regenerate one to stdout with `node lesson-maker/sample-image.mjs freshness > /tmp/lesson-maker-freshness.png`.

## Guides and evidence

[Agent guide](AGENTS.md) · [Contributing/checks](CONTRIBUTING.md) · [Architecture](docs/architecture.md) · [Conventions](docs/conventions.md) · [Design/limitations](docs/design.md).

Automated, isolated-PTY, real-Pi and native-Herdr evidence are recorded separately in [Contributing](CONTRIBUTING.md#verification-record). Native Herdr mouse forwarding with a physical pointer, Kitty placement with real cell metrics, contrast and first-time usability remain unverified. ASCII authoring baseline; no multilingual or accessibility certification. Prompts sent to models contain the lesson's text; they go wherever the chosen Pi provider sends them. With the API backend, picture prompts go to OpenAI's Images API under `OPENAI_API_KEY`. The history folder keeps copies of the lesson and the whole chat text on disk beside it, until removed by hand. Reading aloud sends each slide's speaker notes (or title and text) to Google's Gemini API under the Google key Pi has stored, and may be charged there; the audio is kept in memory for the last eight slides and in a private temporary folder only while it plays. It needs macOS for `afplay`. The aim check sends each message, the last six chat messages (up to 800 characters each), the current slide's name and every slide's title to TypeSafe (api.typesafe.ai) under the key `pi-typesafe` has stored, and may be charged there; Lesson Maker turns on `pi-typesafe`'s tool (`PI_TYPESAFE_ENABLED=1`) in its own process for this, and only the aim check's sessions get the tool. Repository licensing remains unresolved; no third-party assets/fonts are included.
