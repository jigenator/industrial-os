# Architecture

## Modules and direction

| Module | Owns |
| --- | --- |
| `main.mjs` | CLI validation; `--validate`, snapshot and interactive entry; with no file, the start screen; opens the lesson and loads its pictures. Executable, so it can be linked onto `PATH` as `lesson` |
| `src/start.mjs` | The start screen: the project root (git or current folder), its lessons by date, a new lesson's path, keys and the frame; reads directories only |
| `schema/lesson.schema.json` | The lesson contract (JSON Schema 2020-12) agents follow |
| `src/schema.mjs` | Validator for exactly the schema keywords used, errors as JSON Pointer paths; refuses other keywords at compile |
| `src/lesson.mjs` | Schema load, id uniqueness, file ↔ state mapping (`fromDoc`/`toDoc`), blank and readable-from-invalid lessons, open/atomic write, picture load and copy; the history folder beside the lesson (`historyFolder`, `snapshotLesson`, `appendChat`, `readChat`) |
| `src/seed.mjs` | Types/layout vocabulary and the bundled example lesson (with its pictures) as the snapshot and test fixture |
| `src/model.mjs` | In-memory state, the top-bar `TABS`, target identity, the focused box and its live edit, revisions, active slots, hierarchy, locks (`busy`, `lessonBusy`, `locked`; a running whole-lesson request's claim: `lessonClaim`, `claimCovers`, `claimed`, `planBusy`, checked by every hand change and undo step and, as a fence, by `applyLesson`; the author's slide locks: `isLocked`, `lockHold`, `setLocks`, checked by every change, undo step and `applyLesson`), `applyLesson`, `setPicture` and operation-specific undo |
| `src/prompts.mjs` | What each AI request says (box, whole lesson, picture) and what `[prompt]` shows; the lesson JSON it embeds leaves out saved picture prompts |
| `src/edits.mjs` | Small changes to the lesson file's JSON for the lesson agent's tools: delete, add slide or group, move, set slide fields, set plan, and `updateLesson` (the whole lesson, with saved picture prompts put back where the model left them out); each returns what it did or throws why not |
| `src/scheduler.mjs` | AI requests: box rewrites, whole-lesson changes through validated tools inside what they claim (`claim_slides`), picture generation in either style; FIFO per box, whole-lesson requests one at a time and alone until they claim; abort, streaming transcript entries; the reading tools every request gets |
| `src/documents.mjs` | Reference reading for requests: local files and artifacts (through the artifact CLI named by `LESSON_MAKER_ARTIFACT_CLI`, into a removed temporary folder; links only on `LESSON_MAKER_ARTIFACT_HOST`; unavailable when the CLI is unset) as paged text, HTML to text with script-held slide text, artifact listing; no writes to the project |
| `src/speech.mjs` | Reading slides aloud: `spokenText`, `synthesize` (Gemini `gemini-3.8-flash-tts` over HTTPS with Pi's stored Google key, WAV back), `createPlayer` (afplay `-r` rate `-q 1` on a temporary WAV; pause and resume by SIGSTOP and SIGCONT; `position()`), `fromSecond` (a WAV cut at a time, for a speed change mid-slide), `SPEEDS`, `seconds` (a WAV's length), `VOICES` (Google's 30 with gender and style) and `DEFAULT_VOICE` (Orus); the reader's audio is cached by voice and text, and while a clip plays an `every` timer (250 ms, injectable) sets `s.reading.heard`, the share played, for the spoken-word highlight, and `createReader` (one slide, or presenting from a slide in the editor through `selectSlide`, with the next slide's audio prepared; `s.reading`; `pause()` for the controller, which pauses presenting when a box or the chat composer takes the keyboard). `spokenText` lives in `model.mjs` so the renderer imports no I/O; the notes box draws the spoken-word highlight from `s.reading.heard` |
| `src/pi.mjs` | Finds the installed Pi, loads its SDK with provider and imagegen extensions only, finds the Xiaohei skill, lists models, runs one fresh session per request (reporting tool-input progress), calls imagegen (`imagegenParams`, with the backend `imageBackend` reads from `LESSON_MAKER_IMAGE_BACKEND`) |
| `src/geometry.mjs` | Column plan per window size and chosen widths (outline, workspace, chat or dock; no outline column when `columns.outlineHidden`), `MIN_COLUMNS`, `columnWidth` for resizing one column without moving the other, and bounded aspect fitting |
| `src/render.mjs` | Pure state/size → cells, image requests, cursor and click targets; exported design-system composition only |
| `src/text.mjs` | Display sanitization, ASCII-plus-curated-glyph input, grapheme cursor/deletion, bounded wrapping |
| `src/input.mjs` | Incremental key/paste/SGR-mouse/reply decoder, no terminal I/O |
| `src/controller.mjs` | Key precedence, dialogs (models, file errors, prompt, attach), focus returns, click-to-key mapping and explicit attachment seam |
| `src/png.mjs` | Original bitmap/geometric diagrams, stdlib zlib/CRC PNG encoder, bounded PNG validation and local read admission |
| `src/kitty.mjs` | Conservative capability gate, chunked PNG protocol, per-placement identity/delete/sync; injected writer |
| `src/ground.mjs` | The background under every frame: Lunalee's gradient and dot texture through the design system's `composeSurface`, quiet areas without dots, frosted `surface` strips and the hover lift |
| `src/host.mjs` | Streams/raw mode, alternate screen, modes, resize, incremental repaint, signals/errors, the saver, connecting Pi in the background, teardown; `pickLesson`, the start screen's own loop, which restores the terminal before the app starts |
| `sample-image.mjs` | Explicit generation to binary stdout, never invoked by the live host |

Model/text/geometry/prompts and render have no I/O; seed reads only the bundled example. `lesson.mjs` owns every file read and write; `pi.mjs` owns every model and image call. The scheduler receives the Pi bridge through `connect`, so tests pass a fake. The controller's attachment and picture-copy functions are injectable. Host composes modules, never imports another project's host. The design system is imported by package name through exported subpaths.

## State and flows

The lesson file is the only durable state the app reads back as the lesson; its history folder (below) keeps copies and the chat. `main` opens it (`openLesson`: missing → blank file written; invalid → `readableDoc` plus errors, read only), maps it into state with `fromDoc` (groups with names, one flat slide list, pictures by slide and field) and loads picture pixels. After every handled event the host's draw calls the saver: it maps state back with `toDoc`, and when the JSON differs from the last attempt writes it through `writeLesson` (validate, temporary file, fsync, rename), one write at a time. A refused or failed write sets `s.file` to `invalid`/`error` with its errors; a read-only file is never written. Live typing is not in the file until the box is left; stopping the host saves it first (`controller.flush`). UI state, undo and AI EDIT marks are session-only; the chat is session state too, and its finished entries are also appended to the history, from which the next open shows them as earlier. Stable ids never appear in the UI. Flattening is section title → direct slides → subsection title/slides. Undo stores individual rename/create/swap/transfer/delete operations (a moved or deleted slide by its place among its group's slides, since a whole-lesson change rebuilds the slide list), picture replacements and whole-lesson changes (last 30); destructive removals/newer rename overwrites confirm first. A whole-lesson change (a request's, keyed by its job id, or a group drag) is one entry that keeps, for each slide, outline list (a group's title slide, slides and subsections, or the lesson's sections) and plan part it changed, how it was before the change first touched it and how the change last left it (`noteChange`); undo (`lessonUndo`) puts back only those, keeps everything else as it is now, and refuses when any of them was changed again since, is claimed by a running request, or would move or change a locked slide. Removed-slide requests stop before deletion.

Focus is independent of selection and job activity. `outlineRows` lists section, title slide and slides per group as the spec does; `addParents` gives the groups the outline's add buttons use, beside the current slide; `rowSlide` and `rowGroup` give the slide a row opens and the group it belongs to. `pictureInfo` (prompts) builds what `[prompt]` shows for an image box. `deleteSlide` removes an ordinary slide and `deleteGroup` a section or subsection with its subsections and slides (`groupContents`); both record what they removed, with pictures and edit marks, for `undoOutline`.

Mouse: each frame returns click targets (`{x, y, w, h, act, …}`) and quiet areas beside its cells. Every mouse report sets `s.hover`; render's `hoverHit` picks the target a click would take and marks it (buttons acid, rows `lift`, a text box's outline white). The host redraws a pointer move only when that target changes, then composes the frame over the ground (`surfaced`). The host passes the last frame's targets with each event. The controller ignores releases and other buttons, keeps only dialog targets while a dialog is open, picks the smallest target under the pointer, puts the state where the keyboard would be and then runs the same key action. The wheel scrolls the smallest scroll area under the pointer: an overflowing form box (`s.boxScroll` per box; it keeps the wheel at its ends, so the form never moves under it), the outline, transcript, help or form. A box's click target carries its text area and scroll offset; `caretAt` maps the clicked row and column to a caret index through `wrapRows`, the same wrap that draws the text and places the caret (`caretPos`). Stored offsets, not the frame's, are the base, because several notches can arrive before the next frame; the focused box's caret-following offset (`g.boxScroll`, while `s.caretFollow`) is copied into state before each event. A press on a column line (target `rule`) starts `s.resize`; motion with the button held sets `s.columns` through `columnWidth`, and the release ends it; render passes `s.columns` to `geometry`. A press on an outline row also starts `s.drag` (with `group` set for a section or subsection row, whose release goes through `placeGroup`, one whole-lesson undo snapshot); motion events with the button held (mode 1003) update its target row, and the release drops it through `placeSlide`, an undoable transfer, or cancels. Mode text follows the actual printable-key owner, including modal entry and non-entry pending/readonly states. Entering a field changes target; controls do not. A different slide clears it. Ctrl-G remembers origin; the attach path dialog suspends without applying. Messages capture human-readable stamps and private target identities at send time.

Keys: the host turns on the kitty keyboard protocol's disambiguate mode (`CSI > 1 u` after entering the alternate screen, `CSI < u` before leaving it), because without it a terminal sends Shift-Enter as a plain carriage return. The decoder reads `CSI code ; mods u`: a modified Enter is `newline`, Esc and Shift-Tab are their keys, and the rest are rewritten into the legacy bytes they stand for (Ctrl letters as control bytes, Option as an ESC prefix), so every other key path is unchanged. Ctrl-J (LF) and ESC CR are `newline` too, for terminals without the protocol. Dialog inputs ignore `newline`.

Box heights: `s.boxRows` maps a side-by-side pair (render's `BOX_PAIRS`, keyed by its first field) to a chosen height; render uses it for both boxes, else the default. A press on a box's bottom border (target `box-edge`, smaller than the box's own target) starts `s.boxResize`; motion with the button held sets the height from the pointer row; Option-Up/Down (`box-shorter`/`box-taller`, decoded from the arrows' Alt modifier) step the focused box's pair from its drawn height (`g.boxHeights`). The composer's height is derived from the draft's wrapped rows each frame.

Editing: `focusedBox(s)` derives the text box that owns the keyboard from the view, pane and control; there is no separate editor state. The first edit key in a focused, unlocked box creates `s.edit` (`slideId` or `principle`, field, text, grapheme cursor, base revision). After every handled event the controller saves `s.edit` if it no longer belongs to the focused box, so every way of leaving saves through one path; a click elsewhere saves before its own action. `saveEdit` refuses locked boxes and returns BASE CHANGED when the revision moved, which asks before overwriting. Sending a chat message requires leaving the box, so agents always start from saved text. Render draws the preview from the live edit and lays out the form as fixed bands of fixed-height items (every schema field always present, unused ones dimmed and unfocusable) in one or two columns, scrolled by `formScroll`, or to keep the focused item visible while `formFollow` is set; it reports the shown offset as `g.formOffset`.

AI: the host connects Pi in the background (`s.ai`: connecting, ready with models and the chosen model, or error); the editor works meanwhile and sending waits with a notice. The aim is computed, not stored: `chatAim` gives the focused box (from `s.origin` while the chat has the keyboard), else the selected slide, else the whole lesson when `s.wholeLesson` is set or outside Slides. A whole-slide request (`kind: 'slide'`, `slideId` and no field) runs `runLesson` with only `set_slide` (bound to its slide), `generate_picture` (refusing other slides) and the reading tools, and `slidePrompt`; `busy` treats a job without a field as holding every box of its slide, and the scheduler's `clash` serialises it against requests on that slide. A box request (`kind: 'box'`) starts when no earlier request on that box is pending and no whole-lesson request holds it (one waiting, one not yet claiming, or one whose claim covers the box's slide); it reads the box's revision when it starts, sends `boxPrompt`, and applies the reply with `setField(..., { agent: true })` only if the revision is unchanged. A whole-lesson request (`kind: 'lesson'`) starts when nothing else is pending and locks every box, the plan and the outline (`lessonBusy`) while it waits, and once it runs until its first claim. Its session gets small tools (`delete_items`, `add_slide`, `add_group`, `move_items`, `set_slides`, `set_plan`, from `edits.mjs`), `update_lesson` and `claim_slides` (`ids` of slides, subsections or sections, `plan`, `all`). Every edit tool refuses until the request has claimed something; a claim lives on the job (`job.claim`: `{ ids, plan, all }`), only grows, and ends with the job, whether it finishes, fails, is stopped or review stops it. A claim is refused per item, with the reason returned to the model, for a slide the author locked or a group holding one (`lockHold`), one with another pending request on it or inside it, or one holding the author's live edit (`s.edit`); the plan likewise. `all` is allowed only as the first claim (the model's copy of the lesson is then still current) and is the old whole lock, and `update_lesson` needs it. A claim result also gives the current JSON of any newly claimed slide the author changed after the request's prompt was built. With a narrower claim, `lessonClaim` gives it and `busy` (so the outline's `▒`, the boxes' `▒ WORKING` and every hand change) and `claimed` treat its slides, its groups' title slides, slides and subsections and, with `plan`, the plan (`planBusy`) as held; the scheduler's `clash` lets box, slide and picture requests on anything else start beside it, while whole-lesson requests still clash with each other. Each tool edits `toDoc(state)` as it is at the call, so the author's edits beside the request are never put back, and `applyLesson` is given the claim as a fence (`claimErrors`, comparing the lesson before and after): slides it has not claimed keep their content, groups it has not claimed keep their title slide, slides and subsections (so a move needs its source and destination, an addition its group, a deletion its parent), sections it has not claimed keep their order, and the plan stays unless claimed; a new group needs no claim and joins it. `generate_picture` refuses an unclaimed slide. When a whole-lesson job starts it absorbs the whole-lesson jobs queued directly after it (status `merged`, texts joined in order); `recentChat` leaves out messages still queued. Pi's events reach the scheduler through `onActivity` (thinking, tool input being written, tool start and end, with arguments kept from the start), which drives the live `▸` line and the `· Read …` list. Aim check: with a bridge `judge` (pi-typesafe's `typesafe_evaluate` tool, run directly in its own session as imagegen is; `connectPi` sets `PI_TYPESAFE_ENABLED=1` in its process), the controller's Enter validates with `scheduler.refusal`, clears the draft and chains `route` (one at a time, in order): `suggestAim` asks Jev with `aimCheck` from `prompts.mjs` (message, aim, current slide, last six chat messages, slide titles; the choices from `aimChoices`), returns Jev's top pick when it differs from the aim, or the whole lesson when the `beyond` noul (asked with a slide or box aim) is at least 0.5, within `AIM_DEADLINE_MS`, and on failure leaves a notice and returns null; a suggestion opens the `aim` modal, whose pick calls `send(text, target)` and whose Esc restores the draft. Without a judge or another possible scope, `send` runs at once as before. Every model call goes through the scheduler's `ask`, at `s.ai.model` and `s.ai.effort` (the session's thinking level); it keeps the session's `getContextUsage()` in `s.ai.context` for the status row. `generateImage` maps the effort to imagegen's `thinking` and `quality` (`IMAGE_EFFORT` in `pi.mjs`; low adds nothing). `main` reads the model and effort with `readSettings` before the host starts; the host's `draw` passes them to `remember` (`writeSettings`) whenever they change once Pi is ready. Each changes a copy of the file JSON (`toDoc`), validates it (`validateLesson`, errors with JSON paths returned to the model) and applies it with `applyLesson`, which accepts only pictures the lesson already has and marks changed boxes (and boxes whose style changed) AI EDIT. All changes in one request share one undo entry, keyed by the job id (`group`), which `setPicture` joins too, even when the author's own steps land between them. `generate_picture` runs the picture path, with the model's own prompt if given; Every request (box and whole lesson) also gets `read_document` and `list_artifacts` from `documents.mjs` and Pi's read-only `read`, `ls`, `find` and `grep`, rooted at the lesson's project (`projectRoot`); the Xiaohei skill names its file so `read` finds its references. Each tool success adds a line to the live entry, and `onWriting` shows how much tool input the model has streamed. `pump` runs at most `PICTURES_AT_ONCE` (8) picture requests at once. `generateMissing` adds a `batch` picture request for each of `missingPictures()` (unlocked slides' active image fields with a concept, no picture record and nothing pending on the box); batch requests write no entries of their own: `showBatch` keeps one live chat entry and `batchDone` counts each end, and a failure matching `LIMIT_ERROR` stops the batch's queued requests. A picture request (`kind: 'picture'`), and a picture made after an image-box request, asks the chat model with `pictureRequest` (the slide's place and concept, the whole lesson JSON, and for Xiaohei SKILL.md and every reference file) and uses its reply; a prompt given to `generate_picture` by a request's own model is used as it is. It then has imagegen save into the picture folder, loads and validates the PNG, and sets it with `setPicture` (undoable), recording prompt and model. Each request opens a fresh in-memory Pi session from one shared resource loader and model runtime, and disposes it after; streamed text updates one live transcript entry, repainting at most ten times a second. Review aborts every request at once; turning it off starts only what is still queued. Teardown aborts requests and disposes the bridge. Historical stamps are immutable; completed request bookkeeping keeps a bounded recent tail.

Saved picture prompts: `prompts.mjs` serialises the lesson (and a whole-slide request's slide) without each generated picture's `prompt`; the file and state keep it. Whole-slide and whole-lesson requests get `picture_prompt` (slideId and `image` or `afterImage`), which returns a picture's saved prompt and model, or says there is no such slide, no picture or an attached one; it is listed with what the request read. The small tools edit `toDoc(state)`, which still holds every prompt, and `set_slide`/`set_slides` accept only `picture: null`, so they cannot change one. `update_lesson` (`edits.updateLesson`) puts each saved prompt back on a generated picture the model kept by file without a prompt, before validation; `applyLesson` matches pictures by key-sorted JSON (`canonical`), so the order in which keys come back does not matter. A prompt the model writes itself is still refused as a picture the lesson does not have.

Artifacts: `documents.mjs` reads `LESSON_MAKER_ARTIFACT_CLI` and `LESSON_MAKER_ARTIFACT_HOST` on each call. A source is an artifact when it is a 12-character id (optionally `/vN`) or, with a host set, `https://<host>/<id>`; anything else is a file path. The CLI is run without a shell as `artifacts download <source> --output <temporary file> --json`, printing `{ data: { contentType } }`, and `artifacts list --no-expired --json --limit <n>`, printing `{ data: { files: [{ hostedUrl, filename, fileType, uploadedAt }] } }`; on a non-zero exit a printed `{ error: { message } }` is the reason, else stderr. With no CLI set both tools return that artifacts are unavailable and run nothing.

Image backend: `main` calls `imageBackend()` before opening anything in an interactive start, so a `LESSON_MAKER_IMAGE_BACKEND` other than unset, `subscription` or `api`, or `api` without `OPENAI_API_KEY` present (only its presence is checked), ends the start with exit 2; `connectPi` reads it again and `generateImage` spreads `{ backend: 'api' }` into imagegen's parameters, or nothing for the subscription. imagegen itself reads the key.

History: `historyFolder(path)` is the lesson's file name without `.json` plus `.history`, beside it (`foo.lesson.json` → `foo.lesson.history/`); the start screen skips such folders. The scheduler writes it only when it has a lesson path and the lesson did not open read-only. `start(job)` calls `snapshotLesson` synchronously just before a box, slide, whole-lesson or single picture request runs, and `generateMissing` once for a whole batch (its pictures change the file one by one, so a copy each would add a copy per picture): it reads the saved file, returns without writing when there is no file yet or its bytes equal the newest copy (names sort by time), and otherwise writes `<local time YYYY-MM-DDTHH-MM-SS-mmm>.lesson.json` with `wx`, moving on a millisecond if the name is taken. A copy that cannot be written fails the request before it runs (a chat entry `Failed: Not run: …`, the error's code only) or refuses the batch. `keep(entry, scope)` appends each chat entry once it is final (the sent message; a request's entry when it finishes or is stopped; the batch entry when its last picture ends) to `chat.jsonl` as `{ time (ISO), role, scope (box, slide, lesson or picture), stamp, text }`; a failed append leaves a notice. `appendChat` starts a new line after a cut-off last line; `readChat` skips lines that do not parse and returns the last 200 entries marked `earlier`, which `main` puts in `s.chat` when it opens a lesson interactively. `recentChat` and `aimCheck` leave earlier entries out, and render draws them as earlier.

## Images and lifecycle

Pictures are loaded when the lesson opens and when a request or attachment lands. Attachment reads and copies are async and guarded by controller lifetime/epoch/dialog identity; stale reads cannot replace pixels after exit or cancel. Each dialog serializes admission by locking path input and confirmation while pending; cancellation can open a new dialog without allowing an older completion to win. Admitted pixels render independently of concept text; a missing-concept note stays outside the raster hole. Admission opens with `O_NOFOLLOW`, checks path components and fstat, bounds read size, validates PNG signature/chunks/CRC/decompressed scanline lengths. It rejects symlinks at check time: an already-checked ancestor can still be swapped before open, and `O_NOFOLLOW` protects only the leaf. This deliberate shortcut is acceptable only for a local single-user app reading the operator’s own files; no race-proof traversal is claimed. It rejects unsupported encodings rather than pretending to decode them. Paths/errors are not logged to chat.

Only the current slide requests graphics, at most two. Image rectangles are immutable within a frame; host aspect-fits with a **1:2 cell pixel assumption** (no metrics query/probes). Image/placement IDs are distinct and session-unique; each placement has absolute cursor positioning/restoration. Changed slide/view/layout/placement/picture/overlay/resize/text/exit deletes prior images. Incremental changed-cell runs avoid repainting unchanged raster holes; unchanged image requests send no payload during chat typing or busy-label changes. `NO_COLOR`/plain override forced Kitty.

Raw mode uses Node/libuv's raw TTY mode (IXON disabled); all normal/signal/handled-error paths dispose timers/listeners/images and restore raw state, click reporting (1000/1006), bracketed paste, wrap, cursor and alternate screen. SIGKILL cannot be handled. Extend via the owning module plus tests, not another host abstraction.
