# Conventions

Follow [repository conventions](../../docs/conventions.md). Lesson Maker uses Node 22 ESM, standard library, `node --test`, no build step/dependencies. Private package resolution comes from root setup; no project install is needed. Pi is not a dependency: `src/pi.mjs` imports the installed Pi's SDK by path at run time, and nothing else may import it. The only other network call and programs are the [boundary](../AGENTS.md#boundaries) exceptions: `src/speech.mjs` calls Google's speech endpoint and runs `afplay`, and `src/documents.mjs` runs the configured artifact CLI (`LESSON_MAKER_ARTIFACT_CLI`); no shell, copied fonts/assets or color constants. PNG colors come from exported palette roles. The source test enforces those exceptions, that only `lesson.mjs` (and `speech.mjs`, for its temporary audio) writes files, and that only `pi.mjs` uses dynamic `import()`.

The lesson schema is JSON Schema 2020-12 checked by the project's own validator rather than a vendored library: the schema uses a small keyword set, and the validator refuses any keyword it does not implement, so adding one means implementing and testing it first. Schema descriptions are written for the agents that fill the file; prompts quote them rather than restating field meanings.

Render is pure and bounded. Coordinates are zero-based cells. Tests separately cover the schema and file IO, domain operations, AI requests against a fake Pi bridge (`test/fake-ai.mjs`), text/geometry, PNG/protocol, host cleanup and a real isolated POSIX PTY with Pi deliberately absent. Real-Pi and native Herdr evidence are separate and recorded in Contributing, never claimed from tests. Runtime input caps: 20,000 characters per field/path/composer buffer, 4,000 per chat message; over-cap input retains the prior draft. Transcript is session-owned authoring state: `lesson.mjs` appends its finished entries to the lesson's history `chat.jsonl` and reads them back marked earlier, for display only, never as model context. History copies and chat lines are written synchronously, so a copy lands before its request starts and starts cannot race for a name; every other file write is asynchronous. Tests use the bundled example or synthetic files in their own temporary directories and remove only those.

The example lesson's pictures are project-owned geometric primitives and an original 3×5 bitmap alphabet drawn by `src/png.mjs`, committed beside the example as small PNGs; `sample-image.mjs` regenerates one to stdout. No dependency lockfile is needed because this project installs nothing.

## Adoption gaps

1. No option-group element: the host draws curated `○`/`●` glyphs with a `›` roving cursor and a section label column. All seven Types and six layouts stay visible; the host owns activation and click targets.
2. No editable slide-canvas or collapsible tree element: the canvas is the exported numbered panel with plain content, imageInset and imageLabel inside; the outline composes section-head, scroll-rail, action-label buttons and plain rows with `▾`/`▸` carets, `SECTION`/`SUBSECTION` tags, a `│` rail, `▤`/`≡` marks and the drag target band. Host owns field/target/lock/hierarchy and drag semantics. Apart from the text-field frame below, there is no locally drawn reusable card/tree/frame renderer.
3. No solid labelled text-field frame: input-frame draws corner brackets by design, and the user asked for a solid outline on every box so it is obvious where text goes. Render owns one local `frame` (light grey idle, heavy accent focused, dim unused) for every text box: form boxes, the chat MESSAGE box and dialog inputs. It is the one locally drawn frame; it should move into the design system as an input-frame option.
4. No anchored dropdown element: popup-header and popup-footer frame full dialogs. The picture-style dropdown is drawn by render's `dropdown` from the local `frame` and the option-group glyphs, anchored to its button's recorded cell; it is the only dropdown, by request, and should move to a design-system dropdown if one is added.
5. No clickable-control contract: design-system parts return no hit rectangles, so render records the host's click targets beside the cells it composes.
6. No terminal text-entry/Unicode-width engine: host owns entry, paste and grapheme deletion. Printable ASCII authoring is the baseline, plus the design system's curated one-cell glyphs (such as `·`, `—`, `•`), which typing and paste keep; any other typed character is dropped. Unsupported graphemes display a single `?` without changing source; focusing such a box warns that the saved text keeps them until changed. No multilingual width, contrast or accessibility certification.
7. No hover or frosted-strip treatment for arbitrary chrome: crate-banner owns its tool hover and its frosted strip only. `ground.mjs` reuses the same values (`composeSurface` with Lunalee's gradient numbers, `blendFill` with `FROST_ALPHA`) for the header strip, and lifts a hovered row's ground by 18 per channel. Both should move to a design-system surface option.

Sheet-card/desk-tray were reviewed and deliberately not reused: lesson content is not unread mail or a waiting question. Kitty lifecycle/PNG admission are host responsibilities, not adoption gaps. No design-system changes are part of this project.
