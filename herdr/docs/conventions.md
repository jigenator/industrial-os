# Engineering conventions

The [repository-wide conventions](../../docs/conventions.md) apply. This guide adds only this project's rules.

## Project profile

Herdr desktop app files: mods in plain JavaScript for herdr-app's gpui-kit runtime, a layout and a theme in JSON, checked with Node's test runner and `herdr-app check`. Scope reviewed: the whole project at the revision that added the mod, against Herdr app 0.1.15's documentation in `~/.config/herdr-app`.

## Rules

**The mod imports only inside its folder.** The files that draw may import the app's `gpui-kit`, `gpui-base` and `herdr`: `main.js`, `storybook.js`, `stories.js`, every file in `parts/`, and the two views `plate/view.js` and `reloader/view.js`. `reloader/view.js`, alone, also imports `net` for its guard socket, and `parts/drawings.js`, alone, `fs/promises` for its drawings. Everything else is a relative path to a file of the same mod (`./name.js`, `./parts/name.js`, and `../name.js` from a part), or, from a pure module, a design-system file in the mod's `ds/` copy (`../ds/<design-system path>.mjs` from `plate/`). Imports are static: no `import()`.

**One mod, one folder per piece.** The sidebar's files are at the mod's top and in `parts/`; the pane header is `plate/` and the Pi Reloader `reloader/`, each a `view.js` that draws and pure modules beside it. Those two import nothing from outside their folder but `ds/`, `parts/drawings.js` (the mod's folder name) and, in the pane header's view, `signals.js`, the mod's one reader of the `io.signals.v1` label, and no part imports them, so each can still be read, tested and reasoned about alone. `main.js` picks the piece from `props().part` and, for those two, only hands the view `init`, `render` and `close`. A command a piece answers carries its name (`reloader-reload`): every copy of the mod hears every command, so a bare `reload` would be heard by all of them. Why one mod: [decision](../../docs/decisions/herdr-combined-mod.md). Check: `test/industrial-os-layout.test.mjs`, `test/industrial-os-root.test.mjs`. No repository paths and no npm packages: the folder is copied into `~/.config/herdr-app/mods/` as it is. `ds/` is never edited by hand: change the design system, then run `node herdr/scripts/sync-design-system.mjs`. Check: `test/industrial-os-layout.test.mjs` (every file of the mod), `test/droid-plate.test.mjs` (which also checks `ds/` byte for byte against the import closure).

**Rules live in pure modules.** Parsing, state, formats, the finished rule, aggregation, the missions, the map's world and frames, and every SVG drawing are plain modules with no `gpui-kit` or `herdr` import, so Node tests run them. `main.js` keeps only reading Herdr, remembered state, `git` lookups, commands and placing the parts. Check: the same test; review.

**A part takes its data as arguments.** Each piece of the sidebar is a file in `parts/` that returns elements from the theme, plain data and handlers it is given; it reads no pane, space or agent from Herdr and runs no command, so the storybook can draw it on invented data. Its contract is the comment above its export. It names every element that moves, hovers or scrolls through `partId`, so a view may draw it twice under `scoped`. It never imports `main.js`, the storybook or the sample. Every part has a story with a state for each form it takes, unknown values and overlong text included. Details: [parts](parts.md). Check: `test/industrial-os-layout.test.mjs`, `test/industrial-os-parts.test.mjs`.

**Keep render cheap.** herdr-app interrupts a render after about 50 ms (measured with `herdr-app check`), and its JavaScript runs roughly 25–40 times slower than Node. Compose design-system output in a task or a timer callback and let render draw what it left, as the pane header does. Every redraw redraws the whole window, so motion is native where Herdr can express it (`.transition` on opacity, width, left or top; `.loop`; `.frames`), drawn once at its start and once at its end; only a motion that changes characters runs a frame timer, and only while it plays. The sidebar's map and ground light are positions Herdr cannot express, so each runs a 33 ms timer in its own nested view, which keeps the list from being rebuilt. Check: review; the droid-plate harness in [contributing](../CONTRIBUTING.md#droid-plate-pane-header).

**Use only what the runtime has.** No `setTimeout`/`setInterval` (use `cx.timer`), no `Intl`, `TextDecoder` or `WebSocket`, no top-level `await`, and never keep a `cx` for later; each callback gets its own. Timers redraw only when something shown changes: the data clock when a shown age would, the mark clock while a moving mark is shown, the map's in its own nested view. Use native `frames` and `loop` for anything that only repeats. Check: the layout test rejects the missing globals; review for the rest.

**Unknown is never zero.** A missing, malformed or stale label value is unknown and shown as unknown (`??`, `--%` or absent), never as `00`, clean or a completion. One operator-chosen exception: the plate's droid count leaves unknown subagents out ([design](design.md#top)). Check: `test/industrial-os.test.mjs`.

**State is never color alone.** Codes, icons and marks (`*`, `●`, `#?`) carry every state; color only adds emphasis.

**Colors are theme names or design-system values.** The sidebar's state colors are `theme()` names, so they follow the selected theme; every other color and opacity is the design system's [sidebar vocabulary](../../design-system/foundation/README.md#sidebar-vocabulary). The Pi Reloader uses `theme()` names only. The pane header draws the design system's own lines, whose colors are its values (through `ds/`), and has no hex value of its own. A mod cannot import a package, so `mods/industrial-os/vocabulary.js` and `marks/*.svg` are committed copies written by `node scripts/sync-vocabulary.mjs`; never edit them. A theme file restates design-system values (JSON cannot import), each checked against the package. A color the design system does not export is added there first. Check: `test/app-theme.test.mjs`, `test/industrial-os-sidebar.test.mjs` (the copies equal the design system); review the mod for hex values.

**Drawings are written to a hidden folder.** herdr-app draws blur, masks and patterns only from SVG files, so the pure modules return SVG documents and `parts/drawings.js` writes each once to `mods/industrial-os/.gen/`, named by its content; a part asks for one by key with `picture` and draws without it until it is written. The folder is hidden because saving a visible file in a mod's folder reloads the mod. Never commit it.

**Checks never touch a live Herdr.** Tests read files, and load the mod's drawing code only on the stand-in (`stand-in/`), where `hc` always fails and no socket opens; `herdr-app check` loads the mod with in-memory state; an [isolated app](../CONTRIBUTING.md#isolated-app) is a second Herdr with its own home and core. Installing, `herdr-app do`, `layout.*` and `mod.*` commands change the running app and belong to an operator.
