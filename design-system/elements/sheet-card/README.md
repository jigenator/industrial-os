# Sheet card

One shared supplied-state contract for cards, STACK and ^P list rows. Frozen `SHEET_STATES` presets feed the existing state-chip **word form**, not Tatsu state inference: `unread ◆`, `read`, `waiting on you ●`, `answered`, `declined`, `delivery waiting ●`, `withdrawn ↷`. `cardState({state='unread',answer=''}, {maxWidth=Infinity,measure?,preset=SHEET_STATES}) -> Line` adds an optional ` · answer` after answered. Withdrawal is a settled state for a question no longer awaiting an answer, with decorative state/heading ink and a trailing `↷` cue. Delivery state, read state and answer-time copy are all host decisions. Use `heading.state:'withdrawn'`, `kind:'question'` and `read:true` for a withdrawn question card; the host supplies the read flag rather than the renderer inferring it.

- `cardHeading({mark='▤',kind='SHEET',number,time,state,answer?}, {width,measure?,preset=SHEET_STATES}) -> Line`: `▤ SHEET number  time` left, common state right; no leader. Mark must be exactly one curated `GLYPHS` character (not arbitrary ASCII), otherwise `TypeError`. Kind is text or a measured slot; `''` omits the word and its following space. Number is a supplied text slot, including any zero padding.
- `sheetCard({heading={},kind='info',title,gist=[],footer='',read=false,hover=false,button='open',readouts=[]}, options) -> Line[]`: info is five rows (heading/title/two prewrapped gist rows/footer), or four with `footer:null`; question is always three (heading/title/one gist). Gist admits at most two supplied rows. Read removes the tint band and brackets the real action-label. Hover changes ink/band, never row count; a hovered read card keeps no band but brightens its title to primary and its `[open ▸]` to `wheatHi`, so a clickable read card still answers the pointer. Host supplies explicit matching heading state and read flag.
- `stackRow({label,title,state,answer?,selected=false,hover=false,last=false}, options) -> Line`: tree in columns 1–2, stripe column 3, immediate ▸ column 4, then label/title/state. Selected state-ink fill is immediate; host may compose wipe with stateCells opt-in on a separately reserved structural/style region. Read STACK rows retain the tint.
- `stackCard({heading,rows=[]}, options) -> Line[]`: one `▤ STACK` row and caller rows. Only final tree join is derived; membership, pinning, count/time wording, focus and navigation are not inferred.
- `sheetListRow({...row,updated?}, options) -> Line`: ^P row pieces without tree leaders, with fixed left-aligned state/updated columns and a title-to-state dot leader. Filter, sort, paging and narrow stacked-record routing remain host-owned; use document-block's table/record fallback when values must be preserved instead of clipping a one-row list.

`options` is `{width,measure?}`, with `preset=SHEET_STATES` additionally supported by `sheetCard`, `cardHeading` and `cardState` only. STACK and ^P continue to use `SHEET_STATES`. State yields no invented status. At narrow widths optional title/metadata clip before the reserved right state; at extremely small widths only the leading structural cells fit. No click/activation behavior is returned.

## Caller presets and title readouts

A preset is an own-key state map of `{code,shape,tone,hoverTone?,headingTone?,bold?,frameTone?}` entries. Unknown or inherited state keys throw `RangeError`. Code is text or a measured slot (a slot requires `measure`); shape is empty or one curated glyph/ASCII cell, appended after the code by state-chip's word form. Tones are concrete palette roles or exact `#RRGGBB` colors, not terminal-default channels. Invalid entries, colors, shape/code types or nonboolean `bold` throw `TypeError`.

- `tone` inks the state word. `bold` overrides its weight (default: true only for state key `unread`), including measured code spans. The `answered` key alone still appends ` · answer`.
- `frameTone` inks the unread stripe and action plate independently of the word (default: `tone`). For a bone frame with a colored word, also set `headingTone` to bone.
- `headingTone` overrides the heading mark/kind/number ink. Otherwise the keys `read`, `answered`, `declined`, `withdrawn` use decorative ink; others use `tone`. Explicit rich-slot styles survive. Time remains decorative.
- `hoverTone` overrides the hovered frame ink. Otherwise the existing unread/waiting/answered/declined hover inks apply, then the normal frame ink. Read cards still use a ghost stripe and transparent bracketed action; hovered read actions retain `wheatHi`. These are not lifecycle inferences from custom state names.

`readouts` is a line of spans after the title and before the action, separated from each by one band-colored space. Its full width and the action width are reserved before clipping/padding the title. Omitted/undefined or `'default'` readout backgrounds take the current band; explicit backgrounds (including keycaps) and foreground/bold/italic/underline are kept. Spans must contain printable ASCII/curated glyphs without a measurer, or safe whole-grapheme measured text with one. Controls/bidi, invalid styles and cross-span split graphemes are rejected even if the readout would be clipped. No input spans/styles are modified.

`button:null` removes both action and preceding gap; `button:''` still renders the empty action plate and its gap. `footer:null` removes the info footer row, while `footer:''` keeps a blank row. At tiny widths oversized readouts/actions are ultimately clipped left-to-right with the whole band, just like the reference layout; retaining complete tail content beyond the available cells is not guaranteed. Empty/omitted `readouts` and all other omitted new options preserve existing spans and ANSI byte-for-byte.

## Shared contract

Pure spans only; no I/O, clock, parser, state inference, hit targets or input handling. Block rows are exactly `width` cells (integer 1–1000); arrays of supplied rows are bounded to 1000. Inline budgets are 0–1000 or Infinity. Inputs are copied, never mutated. Invalid input types throw `TypeError`; invalid dimensions, states and ranges throw `RangeError`.

Every caller text field accepts a string (the historical printable-ASCII sanitization) or a [measured text slot](../../foundation/README.md#measured-text-slots), with a supplied `measure`. Slot styles, including italic/underline, survive; unsafe controls/bidi, forged widths and split graphemes are rejected. Rich styles must keep semantic cues readable. Default chrome backgrounds are explicitly transparent (`bg:'default'`), not implicit black. Explicit bands and plates are surface-compositor inputs; alpha policy stays in the host. Plain output keeps semantic words and shapes.

## Review refinements

`sheetListRow` additionally accepts `columns:{state,updated}` in options: zero-based left-aligned cell positions, defaulting to W−30/W−8 (with the selection gutter taking priority at tiny widths). Updated must follow state; positions are integers 0–1000 and clip at the viewport. Use these same positions for the host's STATE/UPDATED headers. An unselected list row has no tint and uses the canonical floor dot leader from title to state. A selected read list row fills wheat, not grey. STACK read rows, unlike read standalone cards and list rows, retain their tint. Card footers use decorative ink, read titles secondary, unread state words bold, and read card/list stripes ghost.
